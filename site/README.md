# The learning site

A static, offline-first W3Schools-style site for the Autonomous AI Code Reviewer.
Thirteen parts, 108 lessons planned; sixteen are written (0.1–0.4 and 1.1–1.12).

**This site is a learning aid; `docs/learning/` is the source of truth.**

## Open it

Double-click `site/index.html`. That is the whole installation.

No server, no build step, no npm, no framework. The site is vanilla HTML, CSS and
JavaScript, and every content file is a `.js` file loaded by a `<script>` tag —
which is why it works on `file://`, where `fetch()` of a local JSON file is
blocked. Opening `index.html` from a web server works too, but nothing requires it.

## What is where

```
site/
  README.md                      this file
  index.html                     the parts list, search, progress, theme toggle
  lesson.html                    one lesson, addressed as lesson.html?id=1.1
  tryit.html                     the split editor, tryit.html?id=1.1&ex=0
  assets/contracts.js            PARTS, storage keys, the markdown subset
  assets/app.js                  router, renderer, page chrome
  assets/sidebar.js              the permanent lesson tree (window.Sidebar)
  assets/search.js               client-side search over titles and concepts
  assets/progress.js             "Mark done" state in localStorage
  assets/pyodide-loader.js       the runner: Pyodide, tiers, output panes
  assets/manifest.js             the ordered list of lesson files
  assets/style.css               tokens, dark theme, print CSS, a11y
  content/part-<n>/lesson-<id>.js  one lesson per file
  content/repo-sources.js        GENERATED: the repo's own files, embedded
  tools/validate_lessons.py      the machine gate every wave must pass
  tools/embed_sources.py         generates content/repo-sources.js
  STATE.md                       the wave log
```

## How the site is laid out

Every page carries the same permanent left sidebar: 13 parts, collapsible, with
the current lesson marked `aria-current="page"`, a tick on anything done, and
every written lesson one click away. Under 900px it becomes a drawer opened by
the ☰ button, closed by Escape, the close button or the scrim, with focus trapped
inside while it is open.

Each lesson shows its position (`Part 1 · Lesson 3 of 12`), a **Check yourself**
quiz of three to five questions with instant feedback — the explanation is shown
whether the answer was right or wrong — and ❮ Previous / Next ❯ buttons at the
foot, where the last lesson of a part offers "Next part". Left and Right arrows
follow the pager unless the reader is typing in a field.

### Try it yourself

Every code example carries a **Try it yourself »** link to `tryit.html?id=…&ex=…`:
an editable pane on the left, the output on the right, a draggable divider, and
Run / Reset / Copy in the toolbar. Reset restores the original snippet exactly.
It reads the snippet from `window.LESSONS`, so it needs no server, and it uses
the same runner, so a `terminal`-tier example shows its command and expected
output instead of a Run button.

## The runner: three tiers, and the project's own code

Every code example declares `run_tier`, and the page behaves accordingly.

| Tier | What happens | Needs |
|---|---|---|
| `browser` | Press **Run**; it executes in the page with Pyodide | stdlib, or a package from the Pyodide distribution — fetched on the first Run |
| `browser-pkg` | Same, after `pyodide.loadPackage` fetches a wheel the distribution ships separately | the network, once |
| `terminal` | No Run button: **Copy**, the exact command, the expected output, and a line saying why it cannot run here | a terminal |

Pyodide runs CPython in WebAssembly, and nothing is downloaded until the first
Run press — the page renders fully with the CDN blocked.

### How the project's own modules run here

`file://` forbids `fetch()`, so the browser cannot read `app/models.py` from disk.
Instead `site/content/repo-sources.js` carries the real files, generated by:

```bash
python site/tools/embed_sources.py           # write the bundle
python site/tools/embed_sources.py --check   # fail if it is stale
```

Before an example runs, the files it declares in `"files"` are written into
Pyodide's virtual filesystem at their real paths, so `from app.models import
Finding` works exactly as it does on a machine — same file, same bytes, no
paraphrase. Lesson 0.1 runs `app/rules.py` over `samples/sample.diff` and gets the
same four findings and the same `block` verdict the CLI reports.

What cannot be imported: `app/config.py` needs `pydantic-settings`, which Pyodide
does not ship, and both `app/db.py` and `app/engine.py` import it. Those two are
embedded for reading and quoting only. `sqlite3` is unvendored from the Pyodide
stdlib, and loading `sqlalchemy` alone did not pull it in during Wave 1.5's
acceptance run, so an example using sqlalchemy must list
`"packages": ["sqlalchemy", "sqlite3"]` explicitly.

### What this is not

Lesson code is arbitrary Python running in the reader's page: it can `import js`
and reach `localStorage` or the network. The site is a folder you chose to open
and its lessons are trusted input — the runner is a convenience, not a sandbox. A
`while True:` in an example freezes the tab, because Pyodide cannot be interrupted
from a `file://` page: a Web Worker cannot be created from that origin, and
`SharedArrayBuffer` needs headers the site cannot set. Runaway output is capped at
64 KB so a print loop cannot eat the tab's memory.

### When it fails

- A **Python exception** is shown as content: the pane prints the traceback under
  "This is what the error looks like:". Run stays available.
- The **runtime cannot load** (offline, blocked, slow): every Run becomes the
  terminal panel, with the command, the expected output and a line saying why.
  Nothing throws, and the console stays clean. A browser example shows its expected
  output when it carries one; a `terminal` example always carries one.
- A **10 MB download** happens on the first Run only, never on page load.

## Progress and theme

Both live in `localStorage`, on the reader's machine, and never leave it:

- `ai-reviewer-learning-progress-v1` — `{"version": 1, "done": {"0.1": true}}`
- `ai-reviewer-learning-theme-v1` — `"light"` or `"dark"`

If a browser refuses storage (some configurations do on `file://`), the site keeps
working for the session and simply will not remember. Nothing throws.

## The validator

```bash
python site/tools/validate_lessons.py     # exit 0 and one summary line when clean
```

Standard library only. It reads `assets/manifest.js` for the path list, parses the
pushed object out of each lesson file, and checks the frozen schema, the id/order arithmetic, the `part_title`
against `CONTRACTS.PARTS`, that every `project_links` path exists (and its line
range fits), that no `concept_md` contains raw HTML, that `content/` and the
manifest list the same files, that both pages load the manifest's lessons in
manifest order, and that each page carries exactly the ids the DOM contract
names — no missing id, no extra one. It also checks that every example carries a
unique, well-formed `id` and that any `quiz` has 3 to 5 questions with a valid
answer index and a non-empty `why`. It also checks that every example declares
a valid `run_tier`, that `runnable` agrees with it, that a `terminal` example
carries `expected_output` and a `why_not`, and that any file it asks the runner to
materialise is actually embedded. It exits non-zero with one line per problem.

## Adding a lesson

1. Write `content/part-<n>/lesson-<id>.js` as exactly:

   ```js
   window.LESSONS = window.LESSONS || [];
   window.LESSONS.push({ ...one object matching the frozen schema... });
   ```

   The object must be **JSON-compatible** (double-quoted keys and strings, no
   template literals, no trailing commas) because the validator parses it as JSON.
   Every example needs a stable `id` (`<lesson id>-ex-<n>`, e.g. `1.3-ex-0`) —
   `tryit.html` addresses examples by it — and every lesson from Wave 2 onward
   needs a `quiz` of 3 to 5 `{q, options, answer, why}` entries.
   `concept_md` is markdown only, and only the subset in `CONTRACTS.MARKDOWN_SUBSET`:
   `###`/`####` headings, paragraphs, bold, italic, inline code, fenced code with a
   language tag, unordered and ordered lists, blockquotes, links, simple tables.
   No raw HTML, no images, no footnotes. Emphasis nests one level — `***both***`
   or `*italic with **bold** inside*`; anything deeper, or the two markers
   crossed, stays literal text.

2. Append its path to `assets/manifest.js`, in lesson order.
3. Add the same `<script src>` to `index.html`, `lesson.html` and `tryit.html`, in the
   same place — the gate fails a page whose list disagrees with the manifest.
4. Run the validator. It fails if the three lists disagree, which is the point.
5. Append a row to `STATE.md`. Never rewrite an earlier row.

## Constraints this site keeps

- No real API keys, ever, and no fabricated numbers or paths. Every lesson cites a
  file that exists; the validator checks it.
- No claimed outcomes. Nothing here says the model layer produced a review, or that
  a benchmark number exists, because in this repository neither has happened. See
  `HANDOFF.md`.
- Test counts, rule counts and module counts are quoted from the repository at
  commit `ca96890`, and only there.
